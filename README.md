# news

金融新聞與研究工作台：全球宏觀、美股、港股／中國新聞、機構研究，以及標普 500＋納斯達克 100 公司申報。支援全歷史閱讀搜尋、觀點比較、圖表證據與研究報告。

RSS 抓取不需要 LLM API key。先保存新聞，只有明確啟動分析時才呼叫你設定的模型。

## 安裝

使用 Python 3.10 或以上版本，在專案根目錄執行：

```bash
pip install -r requirements.txt
cp .env.example .env
```

網頁需要 Streamlit 1.66 或以上版本；更新後請重新安裝依賴並重啟網頁服務。

Windows PowerShell 可使用 `Copy-Item .env.example .env`。真實密鑰和 SEC 聯絡資料只填入本機 `.env`；它與 `data/` 已被 Git 忽略。`.gitignore` 不能撤回已公開的內容，也不能阻止強制加入檔案，提交前仍應檢查 diff。

Windows 安裝依賴後，雙擊專案根目錄的 **`Start-News.cmd`** 即可啟動最新版網頁並開啟 `http://127.0.0.1:8502/`。啟動器優先使用專案的 `.venv`／`venv`，其次使用已安裝的 Python；缺少依賴時會提示安裝命令。服務在背景運行，重複啟動會沿用現有服務。電腦重啟後需再次雙擊；啟動紀錄保存在被 Git 忽略的 `data/`，不包含 token 設定。

`main` 是目前維護的版本，已包含公開新聞來源、多家 AI 服務商及 Investat 整合。更新程式不會覆蓋本機 `.env` 或 `data/`；工作階段中輸入的密鑰在網頁或服務重啟後需重新填入。

## 新聞研判與研究延續

### 貼上新聞後分析

在「新聞查詢」貼上新聞，按原本的「分析」按鈕。結果只顯示幾句繁體中文簡單分析，直接說明可能利好／利空哪些公司或產業，以及原因；下方逐項列出「利好 0–10 分、利空 0–10 分」。兩個分數分別表示這則消息的方向性影響強度，不必加總為 10，也不是上漲機率或預期報酬。評分尺度：0 無明確影響，1–3 輕微，4–6 中等，7–8 強，9–10 極強且須有相稱依據。

原文沒有股票代碼時，仍可按原文公司名稱解釋影響，不憑空補寫代碼或供應商關係。文章附帶的代碼僅作標的識別資料，不是營運事實的證據。產品計畫和技術目標仍須寫成計畫或目標，不能寫成已量產、已獲訂單或已實現的效益；沒有行情或市場預期來源時，不應生成股價漲跌或「超預期」的斷言。

快訊旁直接顯示所引用來源；純貼上文字會標示「貼上的新聞」，不產生假連結。分析頁不顯示本次新增資訊、重複事實、反方因素、下一個驗證點或尚缺資料等報告章節。舊版已保存研判不會自動改寫或被擅自補分，須按「分析」以新版規則產生評分。完整研究報告留在獨立的「研究報告」功能。

「事件歷史、來源與補證設定」可填原文連結，或選擇已有事件。後續消息連到同一事件後，分析會帶入最近三次判斷及其原始材料，說明原判斷維持、加強、削弱、推翻或仍不確定；不同事件請選「建立新事件」。歷史模型判斷只作比較背景，不視為事實證據。

分析結果與原始草稿保存在 `data/news.sqlite3` 的新增事件資料表，既有文章不受影響。相同事件、新聞內容及模型／搜尋設定的再次提交會讀取已保存版本；若該版本較舊，畫面會明示版本時間。重整頁面不呼叫模型。審稿失敗或最後寫入失敗時保留初稿，並顯示未完成狀態。可下載完整研判與證據 JSON，亦保留儲存到日報庫的選項。

每篇新材料最多取 6,000 字元，歷史材料最多各 3,000 字元；介面會提示截斷。一次基本研判通常三次模型請求；啟用補證後最多五次分析請求及兩次搜尋請求。相同輸入的快取避免循序重複提交的費用；同時啟動的不同工作階段仍可能各自產生用量，但不會以不同證據覆寫同一版本。

### 研究報告的補證與前後比較

在「研究報告」使用「議論文式研究報告（建議）」模式，於「研究背景與補證」選擇「延續哪一份研究」。前次正文只作歷史假說，本次仍依選材與證據獨立形成論點，並新增「與上次研究的判斷比較」。舊報告不會被覆寫；舊來源編號也不能直接冒充本次來源。

勾選「缺證據時主動搜尋補充資料」後，論點規劃列出的缺口會觸發搜尋，取得來源後重新規劃，再寫作與審稿。原有「完整研究報告」及「資料缺口簡報」模式繼續沿用原流程；需要主動補證和研究延續時，選擇議論文模式。

### 搜尋設定與驗證

兩個入口的補證均預設關閉。搜尋使用 xAI Responses API 的 Web Search，可另勾選 X 搜尋。分析模型可繼續使用其他服務商；此時另填 xAI key 或設定 `XAI_API_KEY`，不會將其他服務商金鑰送往 xAI。只有按下生成按鈕才會發出請求。未啟用補證時，新聞查詢只分析提供的材料與選定事件的歷史；填入原文連結只保留來源歸屬，不會自動抓取全文。這個入口也不會自動搜尋 X、關聯新聞庫內其他事件或排程推送。

補證最多兩輪，每輪限制一至兩個搜尋回合（`max_turns`）、1,500 個可見輸出 tokens，以及六個有引用位置的來源。這些是流程與輸出限制，**不是固定金額上限**；推理 tokens、搜尋取得資料及分析模型用量另外計費。可在保存結果查看供應商實際返回的搜尋用量，缺少用量資料時不當作零。搜尋失敗不自動重試；保留原材料及尚缺資料。

只有 API 返回的引用網址可成為補充來源，生成文字中的其他網址不能授權引用。搜尋內容標示為「模型搜尋摘要」，不冒充原文全文或獨立核實；重要數字仍需對照原始發布。程式檢查來源 ID 與數字可追溯性，再由模型審稿；這些檢查不能保證因果判斷正確。

離線回歸測試：`python -m unittest discover -s tests`。測試使用模擬模型回覆與暫存資料庫，不消耗 API 額度。評估實際分析品質時，另選 20–30 個同一資訊截止時間的新聞案例，核對事實、引用、新資訊、反證和後續驗證條件；不要只比較篇幅或文風。

## 實時新聞

「實時新聞」是預設首頁，以單欄新聞列表顯示接收的新聞。列表顯示香港時間、原文首行標題與內容預覽；點選新聞會開啟置中的大視窗閱讀全文，關閉後回到列表，無須呼叫 AI。頂部可按日期篩選與搜尋文字，列表底部載入更多。原有今日市場論說及日報生成已移至「研究報告」。

新聞使用 Telegram 頻道來源，資料保存在獨立的 `data/telegram.sqlite3`，按原始發布時間保留最近 **7 天（168 小時）**；修改訊息不會延長保留時間。既有新聞與研究資料的保留設定不變。延長保留期不會恢復先前已清除的訊息。

1. 在 [@BotFather](https://t.me/BotFather) 建立接收用 Bot，把它加入目標頻道。私人頻道可從頻道管理員設定加入 Bot。
2. 在專案根目錄的本機 `.env` 設定 `TELEGRAM_BOT_TOKEN` 和數字形式的 `TELEGRAM_CHAT_ID`。可參考 `.env.example`；不要將真實 Token 提交到 Git。
3. 啟動 News 並開啟網頁後，接收器會在伺服器背景執行；「實時新聞」每 30 秒檢查更新。設定變更後重新啟動 News。
4. 在頻道發布一則新訊息驗證接收。有新消息時，列表顯示提示，點選後載入新消息，避免閱讀期間列表突然重排。滾動 7 天可能橫跨八個香港曆日；日期篩選只顯示仍在保留期限內的新聞。

只保存設定頻道的文字、媒體說明與必要識別資料；媒體本體不下載，沒有文字的媒體訊息顯示類型提示。閱讀視窗顯示已保存的全文，不提供「查看原文」按鈕。頻道編輯會更新已保存訊息。

接收器在每次同步和資料讀取時清除過期內容；伺服器關閉期間不執行清理，下次啟動或讀取時補做。清理只作用於本機 Telegram 來源資料，不刪除頻道內的訊息。Bot API 不提供一般頻道訊息刪除通知，因此頻道刪文不會立即同步刪除本機內容，仍按 7 天到期。

這是新訊息接收，不能補抓 Bot 加入前的頻道歷史。[Telegram 官方](https://core.telegram.org/bots/api#getting-updates) 最多保留未接收更新 24 小時；離線超過這段時間可能漏收，即使本機保留期是一星期也無法補回。請保持 News 伺服器運行；沒有安裝開機常駐服務。

也可用命令列接收，不需要開啟網頁：

```bash
python -m src.telegram_source --once
python -m src.telegram_source --worker
```

收件進度與訊息在同一資料庫交易提交，重新啟動不會重複新增。共用同一資料庫的接收器有互斥保護；不要讓其他電腦或不同資料庫的程式同時輪詢同一個 Bot。已有 webhook 時會顯示設定衝突，不會自動刪除 webhook 或丟棄待接收更新。

## 推送到另一個 Telegram 頻道

在本機 `.env` 設定 `TELEGRAM_NOTIFY_BOT_TOKEN` 與 `TELEGRAM_NOTIFY_CHAT_ID`，使用發送用 Bot 的 Token 和目的頻道的數字 ID。將發送 Bot 加為目的頻道管理員並允許發文。原有 `TELEGRAM_BOT_TOKEN`／`TELEGRAM_CHAT_ID` 繼續負責接收；來源與目的頻道必須不同。Token 不會寫入 Git、資料庫或服務狀態。

推送只涵蓋兩種來源：指定 Telegram 來源頻道的新訊息，以及 `Investat` 新文章。RSS、SEC 和其他新聞來源仍只保存本機。來源去重使用 Telegram 的頻道＋訊息 ID、Investat 的文章 ID，通知只讀來源版本，不受共用新聞庫中 RSS 的合併／更新影響。

Telegram 來源（實時新聞／早間 digest 轉發）一律以聊天文字發送全文（OpenCC 繁體）；超過 Telegram 4096 字元上限時拆成多則文字，不再附 TXT。Investat 短文直接發送正文；超過約 250 字則以標題、原有摘要和來源資訊搭配 UTF-8 `.txt` 正文附件。來源有提供連結才會附上，不會編造文章網址。只取得摘要或片段時會標示內容範圍。中文文字在發送副本中用 OpenCC 轉為繁體，來源網址與本機原文保持原樣；這項轉換不呼叫模型，英文保留原文。

雙擊 `Start-News.cmd` 會同時啟動獨立背景服務；即使網頁已經運行，也會檢查並補啟動服務。關閉瀏覽器不會停止收集或推送，電腦關機／休眠期間不會運作。背景服務將 Investat 設為每 5 分鐘檢查最新 50 篇、無關鍵字篩選，其他已設定來源的排程保持原樣。只為新文章或列表資訊有變化的文章抓取正文；未變的既有文章不在每輪重抓全文。摘要／片段的正文補抓至少間隔 30 分鐘，未變文章的正文檢查至少間隔 24 小時，避免耗盡來源請求額度。人工抓取仍沿用原本行為。Investat Token 必須保存為本機 `.env` 的 `INVESTAT_MCP_TOKEN`；只填在網頁工作階段的 Token 無法供背景程式使用。

Investat 正文介面限流時，正文請求至少暫停 30 分鐘，或等待更長的 `Retry-After`；列表仍按 5 分鐘檢查。列表介面本身限流時，整體抓取會退避並尊重等待時間，重啟不會清除退避。只有正文改動、列表未標示任何變化的文章，會在每日正文檢查時發現。

首次啟用每個推送目的地，先同步目前來源窗口作為基準，不發送既有新聞；基準成功後的新內容才進入持久待發送清單。來源更新已推送的正文時會更新消息；需要變更消息類型時可能另發一則更新。暫時拒絕／限流會退避重試。若送出後連線中斷、無法確認 Telegram 是否已收到，該項標示 `uncertain` 並停止自動重發，以免重複。這種結果需要核對頻道後處理，不能宣稱網路發送恰好一次。

Telegram 來源的通知副本同樣遵守原始發布時間起算的 7 天保留期；過期待發項目不再發送。Investat 介面目前只提供最新窗口，沒有已驗證的歷史回補，因此長時間離線可能漏收。抓取不完整或認證失敗會顯示於服務狀態，不會被當成成功。

```bash
# 持續運行（不依賴開啟網頁）
python -m src.news_service --worker

# 查看各來源／推送狀態；輸出不含 Token 或新聞正文
python -m src.news_service --status

# 停止背景收集與推送，保留網頁與資料
python -m src.news_service --stop
```

服務使用作業系統鎖避免重複啟動；接收、Investat 抓取與發送各自執行，長文章抓取不會阻塞 Telegram 收件。這不會自動建立 Windows 開機工作排程。

## 抓取新聞

```bash
# 抓取 31 個已設定來源，預設不呼叫 AI
python -m src.rss_pipeline

# 列出來源 ID，或只抓指定來源
python -m src.rss_pipeline --list-sources
python -m src.rss_pipeline --source cnbc_top --source rthk_finance

# 抓取後匯出新聞庫
python -m src.rss_pipeline --export data/news.jsonl
```

設定檔是 `config/news_sources.json`。預設只收 feed 中最近 30 天的項目，每個來源最多 50 則；無日期項目會保留並標示日期未知。用 `--max-age-days 0` 關閉日期篩選，`--limit-per-source` 調整上限。這不是歷史新聞回補：來源 feed 本身可能只保留最近數十條。

### 融資、監管與機構研究 RSS

以下 8 個新增 RSS 已接入共用新聞庫，預設啟用，可在「新聞來源」及「研究報告」選擇。訂閱提供新聞、節目文字與更新通知；完整統計、持倉和圖表仍使用「公開核對資料」中的原頁／PDF。

|---|---|---|
| FINRA | `finra_news` 新聞與演講；`finra_notices` 監管公告 | [Follow FINRA](https://www.finra.org/media-center/follow-finra) |
| SEC | `sec_press` 新聞公告 | [SEC 新聞公告](https://www.sec.gov/newsroom/press-releases) |

| CFTC | `cftc_press` 新聞稿通知 | [CFTC RSS](https://www.cftc.gov/RSS/index.htm) |
| State Street | `state_street_signals` Street Signals 官方播客提供的節目文字 | [Street Signals](https://www.statestreet.com/us/en/insights/street-signals-podcast) |

FINRA 的官方新聞及公告訂閱目前使用 HTTP；實際核驗時 HTTPS 同路徑未能通過 TLS 驗證，因此保留官方公布的 URL，沒有關閉憑證驗證。FINRA 公告中的 `Oct 09, 2026` 等發布日按紐約時區解析，不以擷取時間代替。其[保證金統計](https://www.finra.org/rules-guidance/key-topics/margin-accounts/margin-statistics)明確不提供 data feed；SEC 私募基金統計亦仍從 PDF／Excel 讀取。

SCOOS 訂閱是 DDP 的更新通知，未必逐季刊出調查發布，且通知日不是資料觀測日；本次核驗其最新通知為 2026-07-16。預設 30 日篩選會略過較舊通知，需要時可用 `--source fed_scoos --max-age-days 0` 收集現有 feed 歷史。CFTC 新聞稿 feed 本次只提供標題和連結，會標示為「僅標題」並排除於報告研究正文；每週 COT 數字仍讀取官方報表。State Street RSS 只收節目提供的文字，不下載音頻、不生成音頻轉錄，也不代替行業圖表月報。

| 類型 | 已設定來源 |
| --- | --- |
| 官方公告／數據 | Fed 貨幣政策、BLS CPI／就業、BEA、ECB、EIA、國家統計局、人民銀行、港交所、香港金管局 |

除了金管局使用官方 JSON API，其餘使用 RSS／Atom。抓取只取得來源實際提供的標題、摘要、內文片段及連結，不追蹤原文頁面、不繞過付費牆，也不把 feed 內容標作完整文章。

單一來源失敗不會中斷其他來源。CLI 回傳 0 表示成功、2 表示部分來源、覆蓋範圍或分析失敗、1 表示所有選定來源均失敗且沒有保存項目。403 不會重試；暫時性網路／伺服器錯誤最多重試一次。來源可能限制自動存取，例如 BLS 的 feed 在部分環境會回傳 403。

每次命令執行一輪後退出；沒有默默建立背景排程。

### 公開機構研究與披露易

新增五個來源使用各機構的公開頁面／公告查詢，與原有來源共用去重及新聞庫。只收目前公開窗口，不宣稱擁有機構完整研報庫或歷史回補。

| 來源 ID | 保存內容 | 範圍與限制 |
|---|---|---|
| `apollo_daily_spark` | Apollo Daily Spark 的文章日期、作者、摘要與頁面提供片段 | 目前公開頁面提供的文章窗口 |
| `ubs_cio` | UBS CIO House View 播客的標題、日期、摘要及音訊原址 | 不下載音訊或生成逐字稿，不等於全部 CIO 研報 |

## 研究閱讀、關注清單與觀點比較

「研究閱讀」搜尋完整本機庫，支援中英文關鍵字，以及機構、股票代碼、資產類別、主題、來源與日期組合篩選。查詢在 SQLite 中分頁，沒有前 500 篇限制；中文採子字串搜尋，英文使用 FTS5，未提供 FTS5 的 SQLite 會退回完整庫子字串搜尋。機構別名會歸一，原始名稱仍保留；無法確定的機構或市場代碼不會猜測。來源渠道、發布者與作者分開保存。

可把條件保存為關注清單，下次開啟仍保留。關注清單是已保存的搜尋，並非主動推送。Investat 抓取提供 `search`、`ticker`、`institution` 條件；在「新聞來源」或「研究報告」填寫後明確按收集才請求介面，文章數上限仍為 50。

從不同頁加入最多 12 篇文章到比較清單，可先查看按日期排列的來源摘要。按「AI 整理並保存觀點」才使用左側選定模型，整理判斷、原文摘錄、條件與觀點變化。摘錄必須出現在來源快照；變化必須對照同一機構較早文章、相同時間口徑及兩邊摘錄。未通過檢查的內容保留缺口，不能把跨機構分歧當作同一家改口。摘錄存在不代表推論語意已核實，整理結果仍需人工核對。

已保存觀點綁定文章內容雜湊；文章更新後不沿用舊觀點。比較資料可匯出 JSON，所選文章亦可送至研究報告。報告候選每頁 200 篇，換頁保留選材；從閱讀頁明確送入但位於目前篩選外的文章會另外提示。

## 圖表庫

「圖表庫」可匯入 CSV／貼上數據，或保存 PNG、JPEG、WebP 來源圖表。CSV 使用 `date,value,series` 欄位，日期為 `YYYY-MM-DD`，`series` 可省略。每張圖保存機構、原文連結、發布日、指標、單位、觀測期、取得方式、原文摘錄、研究判斷及人工核對標記；可關聯新聞 ID 與當時內容雜湊。

數據圖支援多個序列；圖片只保存原圖，不自動 OCR 或補造數字。外部 OCR 數據須自行核對後匯入，核對標記由使用者明確設定。可搜尋圖表、下載 JSON、封存圖表，並把圖表來源與數據加入報告證據。圖表庫保存於 `data/chartbook.sqlite3`，報告使用當次來源快照，不會因之後封存圖表而改寫舊報告。

## 來源健康與持久排程

「新聞來源 → 來源健康狀態與更新排程」顯示近 30 天收集成功率、最後成功時間、新增／更新／重複數量、可用摘要／內文比例及缺口次數。每次收集追加紀錄，重新開啟程式仍保留；未執行來源標示尚無紀錄。成功率衡量完整回應，可用文字比例以每次選入項目計算，兩者均不代表新聞或全文覆蓋率。

可為每個來源保存不同更新間隔及啟用狀態。排程只收集，不呼叫 AI。網頁可手動執行已到期項目；持續運行須另外啟動前景 worker：

```bash
# 設定、查看、執行一輪；這些命令不安裝系統服務
python -m src.scheduler --configure apollo_daily_spark --interval-minutes 60
python -m src.scheduler --configure hkex_announcements --interval-minutes 15
python -m src.scheduler --list
python -m src.scheduler --run-once

# 持續執行已保存的排程，Ctrl+C 停止
python -m src.scheduler --worker

# 暫停單一來源
python -m src.scheduler --configure hkex_announcements --disable
```

請求失敗會退避重試；只有數量截斷或來源限制才會標示部分成功。排程不會自動呼叫 AI 分析。

## 未來雲端方案（尚未實作或部署）

以下是尚未部署的雲端方案；本機已具備可手動啟動的持久化收集 worker，尚未建立雲端服務、自動啟動或跨程序的 AI 額度控制。

- **全天運行與收集：**雲端服務預計 24/7 運行，每 5 分鐘抓取一次新聞及 SEC 申報通知。收集與 AI 分析分開執行，先保存、去重，再排入分析佇列；超出分析額度的項目留待後續處理。來源發布延遲、抓取週期與排隊時間都會影響結果出現時間，不保證即時推送。
- **分析額度：**任何滾動 60 分鐘內最多 20 次模型分析嘗試。每次實際送出的模型請求都須計數，失敗請求及重試也佔用額度；額度紀錄需持久保存，服務重啟後仍須遵守同一視窗。
- **持久保存：**新聞、分析結果、佇列狀態及額度紀錄需保存在持久化資料庫。候選部署方式是 Railway 搭配 [Volume](https://docs.railway.com/volumes) 保存資料；尚未選定或部署。
- **SEC 名單維護：**定期刷新兩個指數的公司追蹤名單，在七日有效期屆滿前完成更新；若更新失敗或名單過期，仍須遵守現有覆蓋檢查。收集內容仍是申報通知及連結，並非申報全文；全文下載與分析不在目前已完成範圍。
- **網頁顯示：**未來網頁可自動刷新並顯示資料庫中已快取的新聞與分析結果；刷新頁面本身不應觸發新的模型請求。

部署時透過平台環境變數／Secrets 設定密鑰及 SEC 聯絡資料，不寫入程式碼、README 或 Git。以下僅為設定範本，沒有真實密鑰或聯絡資料：

```text
OPENAI_API_KEY=<your-deepseek-api-key>
OPENAI_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-pro
SEC_USER_AGENT=my-news-reader/1.0 contact <your-contact-email>
```

模型名稱與價格在部署前仍須核對帳戶實際可用性及 [DeepSeek 官方模型／價格說明](https://api-docs.deepseek.com/quick_start/pricing/)。以上設定範本不代表已驗證雲端部署或模型呼叫。
